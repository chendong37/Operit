# 02 助手包与记忆边界

## 原状

上游支持角色卡、角色独立配置、记忆、Skill、MCP、ToolPkg 和多角色协作，但没有面向当前团队的统一定义。

## 修改意图

- 建立可版本化、可导入导出的助手包。
- 角色只拥有履行职责所需的工具和记忆空间。
- 手机执行与内容生产分离，执行动作必须经过权限门禁。

## 首批角色

- 知行中枢：接收任务、路由角色、汇总结果和发起确认
- 教研官：课程标准、授课计划、教案、题库和成果材料
- 技术总监：软件方案、代码评审和数字员工协作
- 质量运维官：日志、测试、故障定位和验收证据
- 知识管家：整理个人与团队知识，维护长期事实、来源和记忆边界
- 手机执行官：经过确认后完成允许范围内的手机操作

## 首批 Skill

- 团队宪章：中文输出、先给结论、根因修复并删除被替代的错误逻辑
- 任务路由：按教学、研发、办公和手机执行分流
- 安全执行：执行前展示对象、动作、权限和影响
- 记忆策略：区分长期事实、项目状态、临时材料和敏感内容
- 证据门禁：故障、上线和验收任务必须附带可核验结果

## 记忆边界

- 团队知识：课程规范、研发规范和可共享项目事实
- 项目知识：按项目隔离的需求、决策、状态和交付物
- 个人知识：只在用户选择的本地空间使用
- 敏感内容：密钥、学生隐私、客户隐私和合同原文不进入通用长期记忆

## 预期结果

助手能力可独立于 App 品牌升级，角色之间的职责、工具和记忆范围可检查、可迁移。
