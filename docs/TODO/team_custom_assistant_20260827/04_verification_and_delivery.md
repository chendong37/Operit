# 04 验证与交付

## 验证范围

- 基础档位：安装、模型配置、角色导入、记忆、文件处理和无障碍操作
- Shizuku 档位：授权建立、能力显示、撤销授权和增强工具
- 助手包：导入、升级、角色权限、记忆隔离和版本迁移
- 独立 App：应用标识、共存、签名升级、数据备份与恢复

## 验证原则

- 每项能力都记录设备、Android 版本、权限档位、操作步骤和结果。
- 不具备所需能力的工具必须保持不可执行，并说明准确原因。
- 涉及文件修改、系统设置或对外动作的流程必须验证确认门禁。
- 故障修复必须定位并修正错误的状态、数据流或抽象，删除被替代的错误逻辑。

## 交付物

- [x] 可继续维护的源码分支与精确基础版本
- [x] 助手包、六张角色卡、五个 Skill 和记忆策略
- [x] 手机安装、权限配置、模型配置和迁移说明
- [x] 源码静态验证记录、已知边界与上游同步说明
- [ ] 团队稳定签名 APK（需外部 Android 构建环境与签名材料）
- [ ] 小米 / 澎湃OS 真机安装与权限验收

## 完成条件

源码交付以静态检查通过、助手包可复现打包为条件。首版最终完成仍需在至少一台小米 / 澎湃OS 设备验证普通权限 + 无障碍基线，并在有需要时验证 Shizuku；Root 不属于完成条件。

## 当前构建边界

当前执行环境只有 JRE 17，且缺少 Android SDK/NDK/CMake、JDK 21、未初始化子模块、若干预构建 AAR/原生库、STT 与 Web 资产及签名密钥。因此这里不能诚实地产出可安装 APK，也不能完成真机验证。源码包必须在与上游 CI 等价的完整环境中构建；构建成功后还要执行签名校验、双 App 共存、权限撤销、外部入口鉴权和更新禁用验收。
