# 03 独立品牌与内部发布

## 原状

当前源码使用上游品牌、应用标识和发布配置。用户目标是团队内部独立 App，不需要首版公开上架。

## 修改意图

- 将品牌参数集中到明确的构建配置，不在业务代码中散落替换字符串。
- 使用独立应用标识，使官方 Operit 与团队版可以在同一手机共存。
- 使用团队独立签名，并固定签名材料的保管与更新规则。
- 保留上游来源、许可证和适用的第三方声明。

## 已确定输入

| 项目 | 决定 |
| --- | --- |
| App 名称 | 中文“知行 AI”，非中文 locale 使用“Zhixing AI” |
| 应用标识 | `com.zhixing.ai` |
| 图标 | 绿青折线 / 对勾、轨道与琥珀色节点，透明底 |
| 默认模型 | DeepSeek API；凭据不进入源码或助手包 |
| 测试系统 | 小米 / 澎湃OS |
| 公共目录 | `Download/ZhixingAI` |
| 内部端口 | 工作区 `18093`；外部 HTTP `18094` |
| 更新 | 关闭上游更新检查，待接入团队内部更新源 |
| 分支 | `feat/team-custom-assistant`，基于 `071ad2f65c4486fe475e34a56a34a084b1fc99b8` |

## 尚需构建环境输入

- 用户团队的 GitHub fork / CI 或具备完整依赖的 Android 构建机
- 稳定保管的团队签名密钥与对应 `local.properties` 配置
- 内部 APK 分发地址；在此之前不启用应用内更新

## 预期结果

品牌变更集中、可复查；知行 AI 使用独立应用标识，可与官方版共存。稳定升级还取决于后续所有内部 APK 始终使用同一应用标识和同一团队签名。
