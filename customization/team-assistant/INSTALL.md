# 知行 AI 团队助手包 0.2.0

本包面向本人和团队内部使用，包含五个 Skill、六张角色卡与一份品牌母版。APK、DeepSeek API Key 和 Android 系统权限不在配置包内；角色卡导入也不会自动获得设备权限。

小米 / 澎湃OS 的逐项安装、后台保活、无障碍、Shizuku 与撤权验收步骤见同包的 `HYPEROS_SETUP.md`；本文只保留导入顺序和关键边界。

## 安装顺序

1. 安装知行 AI 内测 APK，完成首次启动。
2. 配置 DeepSeek，并完成一次不调用工具的测试对话。
3. 按“普通权限 + 无障碍”基线配置手机；确有需要时再启用 Shizuku。
4. 导入五个 Skill ZIP，并设为对 AI 可见。
5. 导入角色卡备份，切换到“知行中枢”。
6. 核对全局工具可见性，再按本文末尾的用例验收。

## 配置 DeepSeek

在知行 AI 的模型配置中新建或选择 DeepSeek：

- 接口地址：`https://api.deepseek.com/v1/chat/completions`
- 推荐模型：`deepseek-v4-flash`
- API Key：只在应用的密钥输入框中手动录入

保存后先执行连接测试，再发送一条不调用工具的普通消息。连接测试与对话都成功后，才继续配置手机工具。

配置包不包含 API Key。不要把 Key 写进角色卡、Skill、聊天消息、截图、导出文件或团队仓库；团队成员应使用各自受控的 Key 或由组织统一管理的受限凭据。

## 权限档位

| 档位 | 首版定位 | 能力边界 |
| --- | --- | --- |
| 普通权限 + 无障碍 | 基线 | 普通权限按功能授予；无障碍用于当前设备上可见界面的读取、点击、输入和滑动 |
| Shizuku | 可选增强 | 提供已授权范围内的 ADB shell 能力；不是 Root，重启手机后通常需要重新启动服务 |
| Root | 不配置 | 首版不要求、不引导设备 Root，也不把 Root 作为团队运行条件 |

按需授权通知、文件、麦克风和悬浮窗；未使用语音或悬浮窗时不必授予对应权限。只有需要手机界面自动化时才开启知行 AI 的无障碍服务。无障碍服务可能被金融、支付、身份认证或风控敏感应用识别；不要在这些应用中执行无人值守操作，用完后可关闭服务。

角色卡中的 `toolAccessConfig.enabled` 为 `false`，表示继承知行 AI 的全局工具可见性，不表示“禁用全部工具”。因此首版的角色职责是工作流边界，不是 Android 安全隔离：在全局工具设置中只启用团队实际需要的工具和包，系统权限仍按最小授权配置。

## 小米 / 澎湃OS 基线

不同澎湃OS版本的菜单名称可能略有差异，可在设置顶部搜索对应项目。

1. 在应用信息中允许知行 AI 的必要通知，并按需允许文件、麦克风和悬浮窗。
2. 在“设置 → 更多设置 → 无障碍”中找到知行 AI，只在受控测试设备上开启服务。
3. 在知行 AI 的应用信息中允许后台自启动，并把省电策略设为“不限制”；否则息屏后任务可能被系统终止。
4. 首轮测试时让知行 AI 保持在最近任务中，确认息屏、切换应用和网络变化后的状态。
5. 不需要关闭澎湃OS的系统优化，也不需要解锁 Bootloader 或 Root。

## 可选：Shizuku

只有任务确需 ADB shell、应用安装管理或受限系统命令时才配置：

1. 安装 Shizuku，在开发者选项中开启“无线调试”，按 Shizuku 页面提示完成配对并启动服务。
2. 在 Shizuku 中向知行 AI 授权；回到知行 AI 后确认权限页显示 Shizuku 可用。
3. 澎湃OS若提供“USB 调试（安全设置）”，只有在已明确所需命令且普通无线调试授权不足时才按设备提示评估开启。
4. 重启手机后先检查 Shizuku 服务状态；未重新启动前，相应工具应显示不可用，不得把授权记录当作当前能力。

Shizuku 不是 Root。不要为安装本包而解锁 Bootloader、刷机或安装 Root 管理器。

## 导入 Skill

在包管理页面进入 Skill，逐个选择 `dist/skills/` 中的 ZIP 文件：

- `team-constitution.zip`
- `task-router.zip`
- `safe-execution.zip`
- `memory-policy.zip`
- `evidence-gate.zip`

导入后确认五个 Skill 均无加载错误，并设为对 AI 可见。

从 0.1.0 升级时，角色卡可以直接覆盖更新，但 Skill 导入器不会覆盖同名目录。先在 Skill 管理中仅删除上述五个旧版本，再导入 0.2.0 的五个 ZIP；不要通过卸载应用来升级配置包。

## 导入角色卡

在设置的备份管理页面选择角色卡导入，使用 `dist/character_cards_backup.json`。导入完成后应出现：

- 知行中枢
- 技术总监
- 质量运维官
- 教研官
- 知识管家
- 手机执行官

角色卡使用稳定 ID。再次导入会更新同 ID 的角色，不会创建另一套同名角色。导入后手动切换到“知行中枢”；角色卡保持“跟随全局模型”，因此会使用前面配置的 DeepSeek。

## 品牌母版

`branding/zhixing_ai_mark.png` 是知行 AI 标识的透明背景母版，随配置包提供给团队制作内测说明、课程资料和受控衍生素材。它不是可在应用内导入的配置，也不会自动替换 Android 启动图标；应用图标仍以源码中的 Android 资源为准。对外发布或改变标识前，应由团队确认使用场景和最终导出规格。

## 首轮验收

- DeepSeek 连接测试成功，普通对话能够返回结果；报告中不出现 API Key。
- 知行中枢能判断研发、质量运维、教学、知识管理或手机执行的主责角色。
- 知识管家拒绝把临时日志、密钥和学生或客户隐私写入通用长期记忆。
- 技术总监给出实现后，由质量运维官独立列出复现、验证结果与未验证项。
- 教研官在生成材料前核对课程、对象、学时、模板和表格字段。
- 手机执行官在状态变更前列出对象、动作、权限档位和影响，并等待确认。
- 未配置 Root 时，普通权限与无障碍基线仍可完成已授权的界面测试。
- 启用 Shizuku 的设备在重启后能正确显示服务尚未恢复，而不是继续声称高权限可用。

验收记录要区分“模型回复”“命令已提交”和“目标状态已确认”，并注明测试手机、澎湃OS版本、知行 AI 版本及当时的权限档位。
